# План развития и улучшений Orfeus

**Срез:** 2026-11-14. **Последний опубликованный APK:** [Orfeus 1.17 / build-1032](https://github.com/pdkiller666/Orfeus/releases/tag/build-1032). **Канонический список оставшихся направлений:** этот файл; подробная матрица исходных 26 рекомендаций — в [`recommendations-status.md`](../recommendations-status.md). Статус выпуска сверять по [GitHub Releases](https://github.com/pdkiller666/Orfeus/releases) и Actions, а не только по этому срезу.

## Кратко: что закрыто и что нет

- **Реализовано и опубликовано:** распакованный Android source tree в GitHub; CI с Node-тестами, sample/YIN-проверками, Gradle-сборкой и автоматической публикацией APK; навигация и дизайн разделов; локальные SVG; единый аудиоплеер; кнопка обновления; чек-листы упражнений урока и JSON-перенос; базовая игра «Попади в ноту».
- **Частично закрыто:** пункты первоначального аудита 26 направлений имеют статус «частично» на уровне полной рекомендации. Это не значит, что ничего не сделано: часть UI и логики уже в APK, но остаются проверки на реальных устройствах, педагогическая/брендовая валидация или дополнительные сценарии. Нельзя объявлять такие направления полностью закрытыми без перечисленных критериев.
- **Текущий критический дефект:** в опубликованной 1.17 шарик реагирует по вертикали, но ворота не идут к нему. Причина найдена: `drawGame()` читает `game.elapsed`, а `updateGameFrame()` не синхронизировал это поле.
- **Локальный кандидат 1.18:** `updateGameFrame()` теперь обновляет `game.elapsed`; динамический тест проверяет реальный updater, а мобильный Chromium preview с fake microphone показал сдвиг ворот примерно на 93 px за 0,85 секунды. 55/55 Node-тестов, sample catalog и 15 YIN-проверок прошли. `versionName 1.18` выставлен только локально; этот fix **не отправлен и не выпущен**. Физическая проверка Android ещё не выполнена.

## Ближайшие задачи — по приоритету

| Приоритет | Статус | Задача и критерий готовности |
|---|---|---|
| **P0 — game hotfix** | Локально исправлено, не опубликовано | Получить явное подтверждение на точный payload для 1.18. После успешного Actions установить APK поверх 1.17 без удаления: ворота должны непрерывно двигаться к шарику и пересекать его; попадания/промахи и комбо должны совпадать с визуальным событием. Signing key не менять. |
| **P0 — реальный Android smoke test** | Осталось | На целевом телефоне проверить запрос/использование микрофона, стабильный pitch, вертикальное управление шариком, движение ворот, остановку и экран результата. Зафиксировать модель телефона и Android/WebView-версию. Chromium fake mic не заменяет этот тест. |
| **P1 — pitch jitter и задержка** | Осталось измерить | После проверки на устройстве выяснить, вызваны ли рывки реальной сменой pitch, шумом или ошибками YIN; измерить end-to-end задержку на двух телефонах. Только по измерениям выбирать дополнительное сглаживание, AudioWorklet или нативный аудиопуть. Не выдавать проценты за оценку вокального здоровья/качества. |
| **P1 — доступность и размеры экранов** | Частично | Проверить TalkBack, системный крупный шрифт, контраст, reduced motion, портрет/ландшафт и узкие экраны на Android WebView. Browser preview и статические тесты не закрывают физическую доступность. |
| **P1 — педагогическая калибровка и безопасность** | Осталось | С согласия участников собрать/разметить записи и совместно с педагогом проверить диапазоны, пороги и подсказки. Не включать экстремальные техники или медицинские/безопасностные выводы без отдельного одобрения. |
| **P2 — распевка и метроном** | Частично | Спроектировать с педагогом безопасную последовательность разминки/основной части/завершения; интегрировать уже существующий метроном, не создавать второй; покрыть порядок, таймеры, остановку тестами. |
| **P2 — резервное копирование прогресса** | Частично | Проверить экспорт/импорт, повреждённую схему, повторный запуск и перенос на второе устройство; отдельно решить, нужен ли автоматический backup или системный file picker. |
| **P2 — учительские материалы и студийный поток** | Частично | Подтвердить права/согласие/авторство для каждого публичного sample; проверить fallback и обновление каталога. Домашние задания, расписание и передача прогресса требуют отдельного согласования приватности и ролей. |
| **P3 — масштабные функции** | Не начинать без требований | Сопоставить отсутствующее исходное ТЗ; отдельно решать видео/фото-материалы, фирменный шрифт, интеграции студии, Android push и Google Play AAB. Не строить backend или менять хостинг образцов без нового запроса. |

## Правила изменения статусов и релизов

1. Статус «закрыто» ставить только после проверки критерия готовности; «в коде» и «прошло Chromium» не равны «проверено на Android».
2. Push в `main` автоматически запускает сборку и публичный GitHub Release. До него явно согласовать с владельцем версию и точный список файлов; не считать согласие на прошлый релиз разрешением следующего.
3. Workflow рассчитывает `versionCode` по номеру run. При любом релизе сохранять существующий `orfey-android/app/orfey.jks` и не менять signing configuration.
4. После функциональной правки обновлять этот план, `docs/ROADMAP.md`, `docs/PROJECT_CONTEXT.md` и подробную матрицу рекомендаций по необходимости. После Actions проверить build/publish, tag, APK asset/hash и чистоту `main`.
