# Orfeus — постоянный контекст проекта

**Срез:** 2026-11-14. **Последний подтверждённый публичный релиз:** 1.17 / `build-1032`. **Основная ветка:** `main`. **Репозиторий:** [pdkiller666/Orfeus](https://github.com/pdkiller666/Orfeus). Этот документ — handoff для следующих сессий; актуальные приоритеты перечислены в [`ROADMAP.md`](ROADMAP.md).

## Как устроен проект

- `docs/PROJECT_PLAN.md` — единая сводка закрытых функций, известных дефектов, оставшихся задач и критериев выпуска; `docs/ROADMAP.md` — ближайший порядок работ.
- `orfey-android/app/src/main/` — Android/Kotlin WebView-оболочка и веб-ресурсы приложения.
- `orfey-android/app/src/main/assets/index.html` — основной экранный роутер, дизайн-система, рендер экранов и цикл упражнений.
- `orfey-android/app/src/main/assets/core.js` — чистые голосовые/игровые помощники, в том числе детерминируемые правила ворот и серий попаданий.
- `icons.js`, `samples.js`, `updates.js` — локальные SVG, образцы/аудиоплеер, отображение установленной версии и ненавязчивое предложение обновления.
- `orfey-android/tests/` — Node.js-регрессии логики и UI; HTML inline scripts проверяются синтаксически.
- `samples/manifest.json` и `samples/audio/` — публичный каталог; `scripts/validate_samples.py` и `scripts/test_samples_audio.cjs` проверяют схему/хэши и высоту аудио по YIN.
- `.github/workflows/build.yml` — автоматический CI и публикация APK. Push в `main` создаёт сборку и публичный GitHub Release; Android `versionCode` рассчитывается из номера GitHub Actions run.
- `orfey-android/app/orfey.jks` — существующий signing key, критичный для установки обновлений поверх уже установленного APK.

## Игра «Попади в ноту»: опубликована в 1.17

Запрос владельца: исправить расхождение между обещанным описанием и фактической игрой. Вместо обычной последовательности целевых нот теперь есть игровое поле: частота микрофона ведёт шарик по вертикали; к нему движутся 10 ворот с целевыми нотами; раунд — 20 секунд; допустимая точность попадания ±50 центов. За попадание подряд растёт комбо, промах сбрасывает его. Отображаются следующая нота, число пройденных ворот, комбо и процент попаданий; экран результата сообщает попадания и лучшее комбо. Пояснение говорит о совпадении высоты ноты и не трактует очки как оценку качества/безопасности голоса.

Границы реализации: целевые ноты ограничиваются удобным диапазоном, когда он измерен; вертикальная игровая шкала отображает октаву. Стартовый sample ориентируется на первую ноту плана раунда. Обычный цикл Web Audio/микрофона приложения сохранён; оценки игры считаются по воротам, а не по частоте кадров. В WebView run screen используется canvas и доступны DOM-показатели/live-region для следующей ноты/сводки.

Перед push прошли 54 Node-теста, catalog validation и 15 YIN regressions; в Actions обе jobs (`build`, `publish`) завершились успешно. Локальный Chromium preview 390×844 показал игру и экран результата; внутри preview синтетически смоделированы точное попадание и промах, подтверждены увеличение `hits/bestCombo` и сброс `combo`; ошибок браузера нет. Это **не** подтверждает физическую работу микрофона, системное разрешение Android, задержку, TalkBack или педагогическую пригодность; эти проверки остаются следующими задачами после выпуска.

## Известный дефект 1.17 и локальная правка 1.18

После публикации владелец сообщил: шарик реагирует по вертикали на звук, но ворота не движутся вперёд. Причина найдена в цикле: scoring использовал текущий `t`, а `drawGame()` вычислял позицию ворот из отдельного поля `game.elapsed`, которое никогда не обновлялось. В локальном исправлении `updateGameFrame()` присваивает `game.elapsed=t`; добавленный тест исполняет реальную функцию, проверяет рост elapsed и вычисляет движение ворот в сторону шарика. Кандидат установлен как `versionName 1.18`, но изменения не отправлены в `main` и не выпущены.

После исправления Chromium preview с fake microphone за 0.85 секунды зафиксировал сдвиг первой отображаемой позиции ворот примерно на 93 px влево; JavaScript ошибок нет. Node-набор после регрессии: 55/55; sample catalog и 15 YIN checks также прошли. Это подтверждает игровую временную механику в браузере, но не заменяет тест на Android с реальным микрофоном и разрешениями. Публикация fix candidate требует отдельного согласования владельца.

## Постоянные решения владельца

- Сохранять существующий signing key; APK должен обновлять установленное приложение без удаления.
- Визуальные элементы приложения — по-русски, без системных emoji; для интерфейса использовать offline SVG.
- На карточке упражнения действия «Образец» и «Старт» должны быть сгруппированы и заметны; плеер/загрузка — вторичны, сворачиваемы/ненавязчивы.
- Меньше вертикальной прокрутки: категории, поиск/фильтры, disclosures вместо длинных лент.
- Источник каталога — репозиторий GitHub владельца. Публичная загрузка файла немедленно публикует файл; PR управляет его включением в `main`, но не приватностью.
- Не добавлять backend, сторонний портал или промежуточного хостера образцов без нового запроса владельца.
